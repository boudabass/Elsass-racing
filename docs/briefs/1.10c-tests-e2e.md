# Tâche 1.10c : tests de bout en bout avec Playwright

Brief de l'orchestrateur, 16/10/2026. But : vérifier enfin les Server Actions dans un vrai navigateur. Chrome piloté ne charge pas localhost sur ce poste, mais Playwright lance son propre Chromium.

Branche dev. Le serveur dev de John (port 3000) ne doit pas être touché.

## 1. Installation

- Dépendance de dev `@playwright/test` (dernière 1.x stable), puis `pnpm exec playwright install chromium` (navigateur seulement).
- `playwright.config.ts` : dossier `e2e/`, un seul projet chromium, baseURL `http://localhost:3100`, webServer qui lance `pnpm dev --port 3100` avec `NEXT_DIST_DIR=.next-e2e` et `SMTP_HOST` vide (mail en console), `reuseExistingServer: false`, timeout 120 s.
- `.next-e2e`, `test-results`, `playwright-report` dans `.gitignore` et `.dockerignore`.
- Script `"test:e2e": "playwright test"`. Vitest ne doit pas ramasser `e2e/`.

## 2. Connexion sans porte dérobée

`e2e/aide/session.ts`, avec le client propriétaire (DATABASE_URL_MIGRATION) : crée une team « E2E <horodatage> » (slug e2e-…), ses 11 apps activées, un compte `e2e-<horodatage>@example.test` responsable, et un `core_auth_token` de type lien dont le secret est généré par le test et haché comme l'app (fonctions de `src/core/auth/jetons.ts`). Le test visite `/connexion/lien?t=<secret>`. Nettoyage complet dans un afterAll, même en cas d'échec. Rien n'est ajouté au code de l'application pour les tests.

## 3. Scénarios (`e2e/*.spec.ts`, noms en français)

a. Connexion par lien : arrivée sur /qg, nom de la team, 11 tuiles.
b. Connexion par code : l'aide crée un jeton de type code avec un code connu, le test saisit adresse et code dans le formulaire, arrivée sur /qg (couvre la Server Action du code).
c. Déconnexion par le menu du logo : retour à /connexion, et /qg redirige vers /connexion.
d. Identité : changer la couleur principale, enregistrer, recharger, valeur conservée, un `core_domain_event` settings.identite_modifiee existe pour la team.
e. Apps : désactiver Garage, la tuile disparaît du QG ; réactiver Garage, tenter de désactiver Voiture, message « Requise par Garage ».
f. Rôles et droits : l'aide ajoute un second membre équipage actif ; passer son Budget à lecture, écart surligné, puis « Revenir aux droits du rôle ».
g. Boîte d'actions : l'aide émet saison.action_requise avec deux boutons ; dans le QG, ouvrir la boîte, cliquer un bouton, l'action disparaît et la base a le statut decidee.
h. Mode terrain : activer, recharger, classe `terrain` sur `<html>`, `settings_member_pref.modeTerrain` vrai.
i. Téléphone : viewport 360×740 sur /qg, `scrollWidth ≤ 360`, barre basse visible.

Captures pleine page commitées dans `docs/captures/` : /qg en 1440×900, /qg en 360×740, /apps/settings/identite en 1440×900.

## 4. Règles

- Lancer `pnpm test:e2e` jusqu'à ce que tout passe.
- Un vrai bug de l'app se corrige dans l'app, pas dans le test, et se liste dans le compte-rendu.
- Un scénario impossible proprement : `test.fixme` avec la raison.
