## 1. `aborted ECONNRESET` dans le journal serveur des e2e

Une quarantaine à une cinquantaine de lignes par passe, sans échec de test ni redémarrage du serveur. On ne les compte pas comme du bruit tant qu'on ne les a pas expliquées.
- Relève d'où viennent ces lignes : quelle route, à quel moment du test (fin de test, navigation, fermeture du contexte Playwright). Le log du serveur de test et les horodatages suffisent, pas besoin de suite complète.
- Piste à vérifier en premier : le moteur de synchro (`src/core/synchro/client/moteur.ts`, appels `/api/synchro/tirer` et `/api/synchro/pousser`) n'a aucun `AbortController`. Une requête en vol, coupée par une navigation ou la fermeture de la page, peut produire ces lignes côté serveur. Autres pistes : Server Actions coupées par une navigation, `router.refresh()` annulé, préchargements de liens.
- Si la cause est côté client : annule proprement les requêtes en vol (arrêt du moteur, `pagehide`, changement de session), sans casser la reprise du hors ligne (une opération poussée mais non confirmée doit rester dans la file et repartir). Tests Vitest sur la file : une poussée annulée ne perd pas l'opération et ne la double pas.
- Si la cause est purement la fermeture des contextes Playwright en fin de test et qu'elle est sans effet : démontre-le (lignes horodatées corrélées aux fins de test), et dis-le dans le compte-rendu. Dans ce cas, on ne masque rien dans le log : on documente dans `docs/tests.md`.
- **Point d'arrêt** : avant de toucher au moteur de synchro, envoie-moi le diagnostic (cause, preuve, correctif proposé).
