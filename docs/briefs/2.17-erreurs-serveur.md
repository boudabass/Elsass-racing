# Tâche 2.17 : erreurs serveur du journal e2e

Brief de l'orchestrateur, 17/10/2026. John demande de continuer les corrections.

Le journal du serveur pendant l'e2e de la 2.16 contient des erreurs que personne n'a traitées :
- 44 erreurs Prisma : P2003 (clé étrangère) et P2025 (`coreTeam.findUniqueOrThrow`) ;
- 2 `TypeError: Cannot read properties of null (reading 'id')`, dont une sur `/apps/budget/export` ;
- des `ErreurAcces` (non_connecte, aucune_team) levées par des pages au lieu d'une redirection.

J'ai fait le diagnostic, tu n'as pas à le refaire. Il y a deux causes.

**Cause 1 : l'ordre de nettoyage des tests.** Dans `e2e/aide/fixtures.ts`, la fixture `equipe` ne dépend pas de `page`. Les tests déclarent `({ page, equipe })` : Playwright monte donc `page` avant `equipe` et démonte `equipe` en premier. La team est supprimée (`supprimerEquipe`, clés étrangères désactivées) alors que la page est encore ouverte : préchargements, service worker et événements du bus tournent encore sur une team qui n'existe plus.

**Cause 2 : les gardes ne redirigent pas partout.**
- `teamCourante` (`src/core/auth/team-serveur.ts:51`) renvoie `{ team: adhesion.team }` sans vérifier que `team` existe. `exigerContexte` lit alors `team.id` sur null : c'est la TypeError.
- Le layout `(app)` redirige bien quand le contexte manque (`layout.tsx:30-35`). Mais les pages sont rendues en parallèle du layout, et `accesEcranApp` (`src/core/sdk/ecran-serveur.ts`) appelle `contexteQg()` sans rien attraper. Les routes (`/apps/budget/export`) n'ont pas de layout du tout.

En production, la cause 2 touche un vrai cas : un membre retiré de la team, ou une team archivée, pendant que quelqu'un a l'app ouverte. Il doit être redirigé proprement, pas tomber sur une page d'erreur.

## 2. Redirection commune quand le contexte manque

Dans `src/core/qg/donnees.ts`, ajoute :

```ts
// Sans session : vers la connexion. Sans team valide : vers le choix de team. Les autres erreurs remontent.
export function redirigerSiSansContexte(erreur: unknown): void {
  if (erreur instanceof ErreurAcces && erreur.raison === "non_connecte") redirect("/connexion")
  if (erreur instanceof ErreurAcces && erreur.raison === "aucune_team") redirect("/equipes")
}
```

Puis utilise-la :

- **`src/app/(app)/layout.tsx:30-35`** :
  ```ts
  try { await contexteQg() } catch (erreur) { redirigerSiSansContexte(erreur); redirect("/equipes") }
  ```
  Le comportement actuel ne change pas.
- **`src/core/sdk/ecran-serveur.ts`** :
  - entoure `await contexteQg()` d'un try/catch qui appelle `redirigerSiSansContexte(erreur)` puis relance `erreur` ;
  - dans le catch existant autour de `acces(requis)`, appelle `redirigerSiSansContexte(erreur)` **avant** le test `instanceof ErreurAcces`. Un membre au niveau insuffisant garde l'écran « Tu n'as pas accès à cette app » ; seuls non_connecte et aucune_team redirigent.
- **`src/app/(app)/apps/budget/export/route.ts`** : il passe par `accesEcran`, donc il redirige déjà grâce au point précédent (`redirect()` marche dans une route). Vérifie-le simplement dans l'e2e du point 4.

## 3. Nettoyage des tests après la page

Dans `e2e/aide/fixtures.ts`, fais dépendre `page` de `equipe`. Ainsi, la team est montée avant la page et supprimée après sa fermeture :

```ts
export const test = base.extend<{ equipe: Equipe }>({
  equipe: async ({}, utiliser) => { /* inchangé */ },
  // La page dépend de la team : Playwright la ferme avant de supprimer la team, sinon les
  // préchargements et le service worker tournent encore sur une team effacée.

    await utiliser(page)

})
```
