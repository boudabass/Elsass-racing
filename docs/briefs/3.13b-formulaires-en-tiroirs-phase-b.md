Conditions :
- branche dev ;
- le serveur dev de John (port 3000) est intouchable ;
- aucune migration, aucun changement de logique métier ;
- jamais `git add -A` ni `commit -a` ;
- une étape, un commit ; pas de fusion dans main.

## Vérification légère (obligatoire, voir `docs/tests.md`)

Les serveurs oubliés ont saturé la mémoire de John. Règles pour toute la phase :
1. Après chaque commit : `pnpm typecheck`, `pnpm test`. Rien d'autre. Pas de serveur.
2. Pas de `pnpm build` à chaque étape : un seul, en fin de phase, avec `NEXT_DIST_DIR=.next-build`.
3. E2E : seulement les fichiers de test de l'app touchée (`pnpm test:e2e e2e/<fichier>.spec.ts`), une seule passe à la fois. La suite complète n'est pas lancée par l'opérateur : c'est l'orchestrateur qui la passe.
4. Avant tout build ou e2e : le port 3101 est libre. S'il ne l'est pas, ne relance pas : `pnpm nettoyer:serveurs`.
5. En fin de chaque étape, et après tout échec ou interruption : `pnpm nettoyer:serveurs`. Avant de rendre la main : aucun `node` ni `chrome` de Playwright ne doit rester ouvert.
6. Les captures « avant / après » se prennent sur le build local de l'étape 3 ci-dessous, une seule fois, ou sur l'app dev déployée.

## Étape 2 : conversion, app par app

Après mon accord. Ordre : Budget, Partenaires (reste), Saison, Voiture (reste), Réglages, QG. Un commit par app, avec `pnpm typecheck` et `pnpm test` verts avant chaque commit, puis l'e2e ciblé de l'app.

Pour chaque app :
- les fiches se lisent, avec un bouton « Modifier » (point 7) ;
- le bouton principal porte un verbe précis ;
- les actions qui détruisent ou ferment ouvrent un `TiroirConfirmation` ;
- le tiroir se ferme après succès et la page montre la nouvelle valeur sans recharger ;
- les tests e2e passent par les clics (jamais par l'URL directe, hors entrée) et ferment le tiroir par Échap avant de recliquer en cas de relance.
