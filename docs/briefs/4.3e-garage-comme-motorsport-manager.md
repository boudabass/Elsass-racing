## 1. Diagnostic (lu dans le code, puis étapes 1 et 2)

- `garage_vehicle_component.position` existe (texte nullable). L'index unique (véhicule, type, position), NULLS NOT DISTINCT, WHERE deleted_at IS NULL (migration 20261020165328) autorise déjà plusieurs organes d'un même type avec des positions différentes : **pas de changement d'index**.
- `initialiserGarageDans` crée un organe par type, sans position et sans pièce. `preparerAtelierDans` appelle `initialiserGarageDans`.
- État : `lectures-serveur.ts` lit `piece.kmCumules` et `piece.epreuvesCumulees` ; un organe sans pièce montée n'a pas d'état.
- Pneus : l'état vient du train (`etatPneus(monte, usureEstimeePct)`, `services-serveur.ts` ~l. 164 et `lectures-serveur.ts` ~l. 81). Une pièce sur l'organe pneus créerait deux sources d'état : **d'où le train, et non une pièce**.
- Étape 1 (86676af) : `src/apps/garage/emplacements.ts` (7 types, 14 emplacements) et repères de la vue de dessus dans `positions.ts` (`pointPourEmplacement`). Rien n'est branché sur l'écran.
- Étape 2 (1aa91a1) : migration `20261021100000_garage_emplacements` et `scripts/verifier-emplacements.ts` (script `db:verifier-emplacements`, dans la CI après `db:verifier-garage`).

## 2. Emplacements (étapes 1 et 2)

- [954 §3] position par organe : **déjà prévue**. Découpage en emplacements : [John 21/10] (quatre roues, quatre freins, quatre amortisseurs, transmissions gauche et droite). 954 ne détaille pas le découpage.

| Type (`cle`, [954 Décisions]) | Emplacements (`position`) | Nombre |
|---|---|---|
| moteur, boîte, embrayage | `unique` | 1 chacun |
| transmissions | `gauche`, `droite` | 2 |
| freins, amortisseurs | `avant_gauche`, `avant_droit`, `arriere_gauche`, `arriere_droit` | 4 chacun |
| pneus | `train` (quatre roues dessinées) | 1 |

Total : 14 organes par voiture. Gauche = haut du dessin de dessus, nez à droite (convention de ce brief, à confirmer par John).

- **Migration (option A)** [Orch 21/10, point 1] : une seule migration de données, idempotente, sans suppression. Un organe sans position reçoit le premier emplacement de son type, seulement si l'emplacement est libre. Chaque voiture qui a des organes reçoit les emplacements manquants. Une ligne retirée n'est jamais recréée. Vérification : `db:verifier-emplacements` crée cinq états dans la base de la CI (voiture sans organe ; sept organes sans position, comme team-test-lot-2 ; voiture déjà positionnée ; voiture en conflit ; moteur retiré), relance le SQL deux fois, contrôle.
- **Mesure lecture seule, base dev** (21/10) : team-test-lot-2 : 3 véhicules, 7 organes sans position, 0 pièce, 0 pose, 0 ordre, 0 train, 0 commande. team-essai-dev : 1 véhicule, 0 organe. **Production : non mesurée** (mes règles n'autorisent la lecture seule que sur la base dev ; pas d'accès demandé, [Orch 21/10]).

## 6. Réparation (étape 5) : ce que 954 prévoit

- **Ramené à 954** : la réparation est un **ordre de travail de type réparation** [954 §2 Atelier ; §3 garage_work_order] sur l'organe, ou une **intervention rapide** [954 §2, bouton +] (organe, ce qui a été fait, pièce utilisée). Le coût de main-d'œuvre et le prestataire sont ceux de l'ordre [954 §3].
- Coût de main-d'œuvre saisi : `garage.intervention_facturee` émis [954 §5 ; 962] ; sans coût, rien.
- Droit : écriture [Orch 21/10, point 7].
- **À décider par John** : le libellé du bouton (« Réparer », libellé de John, réparation avant remplacement, ou « Ajouter une réparation », libellé de 954) ; et **la remise de l'état à 100 %** : 954 ne la donne pas, et l'état de 954 §4 se calcule sur l'usure réelle. Tant que John n'a pas tranché, l'ordre de réparation ne modifie **ni l'usure ni l'état**.
- Pas de remise de référence, pas de nouveau champ : les idées de la version précédente de ce brief sont retirées faute de source.

## 7. Remplacer (étape 6) : nom de 954

- Bouton **« Remplacer »** [954 §2, Fiche organe]. Deux voies : une pièce des **pièces de rechange disponibles** du même type (statut en stock) ; ou une **nouvelle pièce** saisie (désignation, marque, qualité, prix facultatif, fournisseur facultatif, durée de vie facultative). Le prix impose le fournisseur.
- **Ancienne pièce** : motif obligatoire (usure, casse, préventif, révision) [954 §3]. **Destination choisie par John, sans défaut** [John 21/10] : réserve (en stock), rebut (cassée), ou vendue. Les statuts « usée » et « en révision » de 954 §3 existent mais ne sont pas proposés par défaut.
- Pièce saisie avec prix : commande saisie directe, reçue immédiatement, pour que `garage.piece_achetee` soit émis [954 §5 ; 962] [John 21/10, point 5]. **Écart signalé** : 954 ne dit pas comment une pièce saisie directement crée la dépense ; c'est la décision 4 de John (section 10).
- Stock : la réserve reste une liste facultative [954 §2, Stock]. Le bouton + « Pièce » crée une pièce en réserve.
