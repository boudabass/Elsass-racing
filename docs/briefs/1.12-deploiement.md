## 3. Redirections derrière le proxy

En standalone avec `HOSTNAME=0.0.0.0`, l'URL vue par Next peut être `http://0.0.0.0:3000` (piège déjà vécu sur le Dico). Toutes les redirections (middleware, `/connexion/lien`, `/invitation`, déconnexion, actions) doivent produire une adresse sur le domaine public : en production, base = `APP_URL` ; en développement, l'origine de la requête. Une seule fonction `urlPublique(chemin, requete?)` dans `src/lib/`, testée. Vérifier en lançant le build de production en local (`NEXT_DIST_DIR=.next-build pnpm build` puis `node .next-build/standalone/server.js` sur le port 3200 avec `HOSTNAME=0.0.0.0` et `APP_URL=http://localhost:3200`) : `curl -I http://localhost:3200/qg` doit renvoyer un `Location` sur `http://localhost:3200/connexion`, jamais sur `0.0.0.0`. Arrêter ce serveur ensuite.
