# Tâche 4.0b : les vérifications lourdes passent sur GitHub Actions

Brief de l'orchestrateur, 20/10/2026. Décision de John du 20/10 : son poste (16 Go) ne supporte plus Docker, les builds et les passes e2e en plus de son travail. Toutes les vérifications lourdes quittent le poste et tournent sur GitHub Actions. **La 4.3 est en pause** jusqu'à la fin de cette tâche : commite ce qui est prêt (point 0 et migration de priorité, après typecheck et vitest), puis passe ici.

Règle de cette tâche : **aucun build, aucune passe e2e, aucun Docker sur le poste.** Tout ce qui est lourd se vérifie sur GitHub. Compte-rendu par SendMessage qui cite tous tes commits.

## 1. Flux de travail

- L'opérateur commite en local, puis pousse sur une branche de vérification **`verif`** (jamais déployée par Coolify), lit le résultat avec `gh run watch` ou `gh run view`, et ne pousse sur `dev` (déployé) qu'avec mon feu vert, une fois `verif` vert.
- Le workflow tourne aussi sur `dev` et sur `main` (filet de sécurité), et à la demande (`workflow_dispatch`).
- Sur le poste ne restent que : l'édition, `pnpm typecheck` et `pnpm test` (vitest, sans base). Plus de `db:up`, ni de `db:verifier-*` en local, ni de build, ni d'e2e.

## 2. Workflow `.github/workflows/verifications.yml`

Un seul workflow, deux jobs :

**Job `rapide`** (environ 3 min) : checkout, Node 22, pnpm 11.21.0 (versions de `docs/stack-reference.md`, cache pnpm), `pnpm install --frozen-lockfile`, `prisma generate`, `pnpm typecheck`, `pnpm test`.

**Job `complet`** (après `rapide`) :
- service `postgres:18` (même version que la production), avec le rôle applicatif créé comme `docker/init/01-role-app.sql` (étape SQL avant les migrations) ;
- `pnpm db:deploy`, `pnpm db:seed`, puis `db:verifier-rls`, `db:verifier-bus`, `db:verifier-synchro`, `db:verifier-garage` ;
- `pnpm exec playwright install --with-deps chromium`, puis `pnpm test:e2e` (la config actuelle construit elle-même le build de test sur le port 3101) ;
- en cas d'échec : `playwright-report/`, `test-results/` et le journal serveur en artefacts (7 jours de rétention) ;
- toujours : le nombre de lignes `ECONNRESET` et `uncaughtException` du journal serveur dans le résumé du job, et le **résumé des captures** : les captures `docs/captures/` régénérées en artefact (le dépôt n'est pas modifié par la CI).
- Une entrée `e2e` facultative du `workflow_dispatch` permet de lancer un seul spec (`pnpm test:e2e e2e/garage.spec.ts`).
- `concurrency` par branche, l'ancienne exécution annulée : on ne paie pas deux fois.

Variables : `SESSION_SECRET` de test généré dans le workflow (pas un secret du dépôt), `DATABASE_URL` et `DATABASE_URL_MIGRATION` vers le service, `SMTP_HOST` vide. **Aucun secret de production ni de dev dans GitHub.**
