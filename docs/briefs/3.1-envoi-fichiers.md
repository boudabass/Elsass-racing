## 1. Service serveur : `src/core/fichiers/`

### 1.1 Règles pures : `src/core/fichiers/regles.ts`, avec tests unitaires

- `detecterType(debut: Uint8Array): TypeFichier | null`. Le type se lit dans les premiers octets du fichier, jamais dans le nom ni dans le type annoncé par le navigateur :

  | Type | Signature | mime stocké |
  |---|---|---|
  | JPEG | `FF D8 FF` | `image/jpeg` |
  | PNG | `89 50 4E 47 0D 0A 1A 0A` | `image/png` |
  | WebP | `RIFF` puis `WEBP` à l'octet 8 | `image/webp` |
  | PDF | `%PDF-` | `application/pdf` |
  | SVG | texte UTF-8 qui commence, après espaces et BOM éventuels, par `<?xml` ou `<svg`, et qui contient `<svg` | `image/svg+xml` |

  Tout le reste renvoie `null`.
- `TAILLE_MAX = 10 * 1024 * 1024`, soit 10 Mo.
- `cleStockage(teamId, fileId, date)` renvoie `${teamId}/${aaaa}/${mm}/${fileId}`. Le nom d'origine n'entre jamais dans le chemin.
- `nomPropre(nom)` : garde le nom d'origine pour l'affichage. Il retire les chemins, les caractères de contrôle et `/ \ : * ? " < > |`, coupe à 120 caractères, et renvoie « fichier » si le résultat est vide.
- `peutLire({ estDansLaTeam, applis, niveaux, estLogoTeam, estAuteur })` : règle de lecture décrite au point 1.3.

### 1.2 Écriture : `src/core/fichiers/fichiers-serveur.ts`

`enregistrerFichier(ctx, { octets, nomOrigine })` :
1. refuse au-delà de `TAILLE_MAX` ;
2. détecte le type, et refuse avec le message « Formats acceptés : photo (JPEG, PNG, WebP), PDF ou SVG. » ;
3. calcule l'empreinte (sha256 en hexadécimal) ;
4. écrit le fichier dans un fichier temporaire du même dossier, puis le renomme : une coupure ne laisse jamais de fichier à moitié écrit ;
5. crée la ligne `core_file` avec `newId()`, `teamId`, `storageKey`, `nom`, `mimeType` détecté, `taille`, `empreinte` et `createdBy`. Laisse `largeur` et `hauteur` à null ;
6. renvoie `{ id, nom, mimeType, taille }`.

`rattacherFichier(client, ctx, { fileId, app, ficheType, ficheId, role })` :
- vérifie que le fichier existe dans la team et n'est pas supprimé ;
- vérifie qu'il a été envoyé par ce membre, ou qu'il est déjà rattaché à cette même fiche. On ne peut pas rattacher le fichier de quelqu'un d'autre ;
- crée la ligne `core_attachment`, sauf si elle existe déjà ;
- les apps l'appellent dans leurs services, au moment où elles enregistrent la fiche.

`remplacerFichier(...)`, quand un fichier en remplace un autre (logo, ticket) : l'ancien `core_file` reçoit `deletedAt`. Le fichier physique reste sur le disque : la purge viendra plus tard.

### 1.3 Routes

**`POST /api/fichiers`** (`src/app/api/fichiers/route.ts`), en multipart :
- champs `fichier` et `app`. `app` est une clé du catalogue (`budget`, `saison`, `settings`…). Tout le reste reçoit 400 ;
- garde : `exigerAcces(app, "contribution")`. Hors session ou sans team, la réponse est 401, jamais une redirection ;
- en cas de refus métier, 400 avec `{ message }` en français ;
- en cas de succès, 201 avec `{ id, nom, mimeType, taille }`.

**`GET /api/fichiers/[id]`** (`src/app/api/fichiers/[id]/route.ts`) :
- la session et la team courante sont obligatoires, et le fichier est lu par `prismaPourTeam` (RLS) ;
- règle de lecture (`peutLire`) :
  - si le fichier a des rattachements, le membre doit avoir au moins `lecture` sur l'app d'au moins un de ces rattachements ;
  - sans rattachement, seuls deux cas sont admis : c'est le logo de la team (`core_team.logo_file_id`), ou le membre en est l'auteur (aperçu juste après l'envoi) ;
- tout refus renvoie **404**, jamais 403 : on ne révèle pas qu'un fichier existe ;
- en-têtes de réponse :
  - `Content-Type` : le mime stocké ;
  - `X-Content-Type-Options: nosniff` ;
  - `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox` : un SVG ouvert directement n'exécute rien ;
  - `Content-Disposition: inline; filename*=UTF-8''<nom encodé>` ;
  - `Cache-Control: private, max-age=3600`.
- le fichier est lu en flux (`fs.createReadStream` converti en `ReadableStream`), pas chargé en entier en mémoire.

Le service worker ignore déjà tout `/api/` (`src/core/synchro/service-worker.ts:69`) : rien à changer de ce côté, vérifie-le simplement.

## 2. Composant d'envoi : `src/components/formulaire/champ-fichier.tsx`

`<ChampFichier app="budget" accept="image/*,application/pdf" libelle="Photo du ticket" valeur={fileId | null} onChange={(fichier) => …} />` :
- un `<input type="file">` relié à son label, avec la classe `cible-tactile` et sans `capture` : le téléphone propose l'appareil photo ou la galerie ;
- **compression des photos avant l'envoi** : un JPEG, PNG ou WebP de plus de 1,5 Mo, ou de plus de 2 000 px de large ou de haut, est redessiné dans un canvas à 2 000 px au plus sur le grand côté, puis exporté en JPEG à 0,85. Les PDF et les SVG partent tels quels ;
- l'envoi passe par `fetch("/api/fichiers")`. Pendant l'envoi, le champ affiche « Envoi… » et ne peut pas être utilisé ;
- après l'envoi :
  - une image montre une vignette de 64 px, `<img src="/api/fichiers/<id>">` ;
  - un PDF montre son nom avec une icône de document ;
  - le bouton « Retirer », en `LIEN`, vide la valeur ;
- en cas d'erreur, le message du serveur s'affiche sous le champ avec `Message`. Si le serveur ne répond pas, le message est « L'envoi a échoué. Réessaie. » ;
- **hors ligne** (`navigator.onLine` faux, ou l'indicateur de synchro déjà présent) : le champ est désactivé et affiche « La photo s'ajoute quand le réseau revient. » Ne mets aucune file d'attente de fichiers en place : ce n'est pas le sujet de cette tâche ;
- valeurs par défaut de `accept` : `image/jpeg,image/png,image/webp,application/pdf`. Pour le logo : `image/jpeg,image/png,image/webp,image/svg+xml`.

## 3. Usages

### 3.1 Logo de la team (Réglages, Identité)

- La rubrique Identité reçoit un champ « Logo de la team » (`ChampFichier`, app `settings`), qui ne peut être modifié qu'au niveau gestion, comme le reste de la rubrique.
- Le service d'enregistrement de l'identité :
  - pose `core_team.logo_file_id` ;
  - rattache le fichier avec app `settings`, ficheType `team`, ficheId = id de la team, rôle `photo` ;
  - remplace l'ancien logo par `remplacerFichier`.
- « Retirer le logo » remet `logo_file_id` à null.
- **Barre haute** (`src/components/qg/barre-haute.tsx:48`) :
  - avec un `logoFileId`, elle affiche `<img src="/api/fichiers/<id>" alt="" class="h-8 w-8 rounded object-contain">` à la place de l'icône `House`. Le lien garde son nom accessible actuel ;
  - si l'image ne charge pas (`onError`, par exemple hors ligne, puisque `/api/` n'est pas en cache), elle revient à `House`. Sans logo, rien ne change.
- L'aperçu des couleurs de Réglages (`apercu-couleurs.tsx`) suit la même règle.
