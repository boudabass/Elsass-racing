# Journal du projet

## 16/10/2026 : relevé de stack, initialisation du dépôt, base locale

- Relevé de la stack d'Elsass Dico, en lecture seule : `docs/stack-reference.md`.
- Initialisation du dépôt : un seul paquet Next.js, versions épinglées sur le Dico (Next 15.5.27, React 19.3.0, Prisma 7.10.0, Tailwind 3 et non 4).
- Radix UI (versions en `^`), sonner, 30 composants shadcn Radix, sonner et `use-mobile`. Non copiés : `form.tsx` (attend react-hook-form, tâche 1.10), `calendar`, `carousel`, `chart`, `command`, `drawer`, `input-otp`, `resizable`, `list-skeleton`.
- Vitest 3.x avec `passWithNoTests`, `outputFileTracingRoot` dans `next.config.ts`.
- Structure `src/app`, `src/core`, `src/apps`, `src/components/ui`, `src/components/qg`, `src/lib`, `prisma`, `docs`, `documentation`.
- Dockerfile en deux étages, entrypoint avec `prisma migrate deploy`, CLI Prisma isolée dans `/opt/prisma-cli`.
- Base locale : `docker-compose.yml` (PostgreSQL 16 alpine, port hôte 5433, volume `elsass-racing-pgdata`, healthcheck). Usage développement uniquement. Scripts `db:up`, `db:down`, `db:migrate`, `db:deploy`, `db:studio`.
- Socle : `newId()` (UUID v7, paquet `uuid` 11.x) dans `src/core/ids.ts`. Conventions du schéma dans `docs/conventions-schema.md`, contrôlées par `src/core/schema-conventions.test.ts`.
- Premier modèle : `CoreTeam` ↔ `core_team`, avec l'enum `CoreTeamStatut`. Migration `20261016141250_init_core_team`, appliquée sur la base locale.
- Aucune authentification, aucun middleware, aucun manifest pour l'instant.
- Schéma plateforme et accès : `CoreUser`, `CoreAuthToken`, `CoreInvitation`, `CoreDevice`, `CoreMembership`, `CoreApp`, `CoreTeamApp`, `CoreRoleDefault`, `CoreAppAccess`, avec les enums `CoreRole`, `CoreAccessLevel`, `CoreMembershipStatut`, `CoreAuthTokenType`. Migration `20261016141717_core_plateforme_acces`, avec le CHECK « email ou téléphone » d'invitation ajouté à la main.
- Catalogue : 11 apps et 44 droits par défaut dans `src/core/catalogue.ts` (source unique), écrits en base par `prisma/seed.ts` (`pnpm db:seed`, idempotent, lancé aussi par `migrate reset`). Aucune team, aucun compte, aucune adhésion créés.
- Référentiels partagés : `CorePerson`, `CoreSeason`, `CoreEvent`, `CoreEventEntry`, `CoreVehicle`, `CoreContact`, `CoreTag`, avec les enums `CoreEventType`, `CoreEventStatut`, `CoreEntryStatut`, `CoreVehicleType`, `CoreContactCategorie`. Migration `20261016142106_core_referentiels`. Relations `personId` de `CoreInvitation` et `CoreMembership` branchées vers `CorePerson`, et les deux index manquants de 1.3 ajoutés (`core_device.user_id`, `core_invitation.envoyee_par_user_id`).
- Services transversaux : `CoreFile`, `CoreAttachment`, `CoreActivity`, `CoreNote`, `CoreTask`, `CoreAlert`, `CoreAction`, `CoreNotification`, `CoreNotificationPref`, `CoreDomainEvent`, `CoreEventDelivery`, `CoreSyncCursor`, `CoreSearchIndex`, `CoreExport`, avec 9 enums. Migration `core_services` : colonne `vecteur` générée et index GIN ajoutés à la main. Liens `logoFile`, `photo` branchés vers `core_file`. Inventaire des 31 tables dans `docs/schema-core.md`.
- Plein texte : la colonne générée `vecteur` de `core_search_index` est remplacée par une colonne ordinaire, tenue à jour par le trigger `core_search_index_vecteur_trg` (fonction `core_search_index_maj_vecteur`). Index GIN déclaré dans le schéma avec `@@index([vecteur], type: Gin)` : Prisma l'accepte. Migration `core_search_trigger`. `prisma migrate diff` renvoie une migration vide. Test plein texte : « Rallye du Florival » puis UPDATE en « Slalom du Gaschney » donne florival 1 → 0, gaschney 0 → 1 (transaction annulée).
- Flux des migrations : `pnpm db:migrate` devient `prisma migrate dev --create-only`. Toute migration est créée, relue, complétée au besoin, puis appliquée par `pnpm db:deploy`. Documenté dans `docs/conventions-schema.md`.
- Authentification : connexion par lien mail ou code (`src/core/auth/`), sessions JWT signées avec appareil en base, cookie de team, choix de team, middleware de session. Pages `/connexion`, `/connexion/lien` (route), `/equipes`, `/qg` (provisoire). Mail par nodemailer : STARTTLS sur 587, TLS direct sur 465, expéditeur `info@theelsassisch.com`, console hors production sans SMTP. Script `pnpm team:creer`. Team Koehling Racing Team créée en local. Documentation dans `docs/auth.md`.
- Droits et cloisonnement : niveaux et résolution (`src/core/droits/`), garde `exigerAcces` et messages `libelleErreurAcces`. RLS sur les 25 tables qui portent `team_id`, plus `core_team` et la lecture des adhésions du compte. Rôle applicatif `elsass_racing_app` (NOLOGIN) et connexion `elsass_racing_app_dev`. Deux URL : `DATABASE_URL` (app, RLS) et `DATABASE_URL_MIGRATION` (propriétaire). `prismaPourTeam` et `prismaPourCompte` fixent le contexte par transaction. Durcissement : mail envoyé seulement à un compte existant ou invité, rien pour une adresse inconnue. Vérification `pnpm db:verifier-rls`. Documentation dans `docs/droits.md`.
- Contrat d'app : catalogue de 72 événements (71 d'apps et `core.action_decidee`) dans `src/core/evenements/catalogue.ts`, avec `estNomValide`, `emetteurDe`, `abonnesDe`. Manifeste `ManifesteApp` et `validerManifeste` (`src/core/sdk/manifeste.ts`). Catalogue de 38 widgets dans `src/core/sdk/widgets-catalogue.ts`. Registre `src/apps/registre.ts` (Réglages seul pour l'instant). `appsVisibles` assemble les apps visibles, Réglages en dernier pour le responsable. Documentation dans `docs/app-sdk.md`.
- Bus d'événements et boîte d'actions : `emettre` (écrit l'événement et les livraisons, puis traite immédiatement, choix provisoire du lot 1), registre de gestionnaires (`src/core/evenements/gestionnaires.ts`), gestionnaires du socle pour `*.action_requise` et `*.action_levee`, `decider`, `reporter`, `listerActionsEnAttente` (expiration à 30 jours). Filtrage, regroupement et règle « Prochaine étape » en fonctions pures. Vérification `pnpm db:verifier-bus`. Documentation dans `docs/evenements.md`.
- Enveloppe du QG : grille des apps, barre haute, navigation, boîte d'actions (formulaires serveur), bouton « Prochaine étape », menu « + » filtré par le rôle, recherche, mode terrain (cookie), bandeau jour d'épreuve. Thème clair et sombre, couleurs de team avec contraste contrôlé, polices Barlow. Données réelles de la team Koehling (`pnpm donnees:koehling`). Documentation dans `docs/qg.md`.
- Manifestes des dix apps : `src/apps/<cle>/manifest.ts` pour saison, budget, partenaires, voiture, garage, equipe, checklist, documents, medias, dashboard. Identité alignée sur le catalogue, widgets tirés de `WIDGETS`, événements dérivés du catalogue (`evenementsEmisPar`, `evenementsEcoutesPar`). Registre à 11 manifestes dans l'ordre du catalogue. Le QG affiche ses 11 tuiles.
